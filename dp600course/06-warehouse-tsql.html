Deep dive: more surface-area and type details
  • Also supported: SELECT … INTO, sp_rename, scalar UDFs, nested CTEs (preview), GROUP BY ALL, FROM-first syntax, a subset of hints, OPENROWSET, DDL inside transactions. ALTER COLUMN in preview.
  • Not supported: SET TRANSACTION ISOLATION LEVEL (always snapshot), SET ROWCOUNT, PREDICT, sp_showspaceused, named/marked/distributed transactions, savepoints, vector type. FOR XML; FOR JSON only as last operator.
  • Unenforced keys still help: tools detect relationships, the optimizer can use them.
  • More types: datetimeoffset → datetime2 (+ AT TIME ZONE); text/ntext/json → varchar; xml → none; geography/geometry → lat/long, WKB varbinary or WKT varchar. varchar(max)/varbinary(max) up to 16 MB. uniqueidentifier stored as binary (not readable from the endpoint).
  • Unsupported types are fine in variables/parameters, not in tables. Default collation Latin1_General_100_BIN2_UTF8 (case-sensitive); a CI collation can be chosen at creation (e.g. REST API).
  • The surface area changes often: check Microsoft Learn "T-SQL surface area" when migrating.

COPY INTO dbo.StageCustomer (CustomerID 1, CustomerName 2, City DEFAULT 'Unknown' 3)
FROM 'https://contosolake.dfs.core.windows.net/raw/customers/*.csv.gz'
WITH (
    FILE_TYPE  = 'CSV',
    CREDENTIAL = (IDENTITY = 'Shared Access Signature', SECRET = '<sas>'),
    COMPRESSION = 'Gzip',
    FIRSTROW   = 2,
    MAXERRORS  = 10,
    ERRORFILE  = '/rejected'
);
  1. Target must exist. Map columns by position, with defaults.
  2. Wildcards load many files at once.
  3. Auth: Entra ID (default, no CREDENTIAL), SAS (Read + List), key, or Workspace Identity for firewalled storage.
  4. Gzip CSV, skip the header row.
  5. Tolerate 10 bad rows; write them to a _rejectedrows folder (CSV/JSONL).
CREATE TABLE gold.FactSalesDaily
AS
SELECT  d.DateKey, p.ProductKey, c.CustomerKey,
        SUM(s.Quantity * s.UnitPrice) AS SalesAmount
FROM    silver.Sales     AS s
JOIN    gold.DimDate     AS d ON d.[Date] = CAST(s.OrderDate AS date)
JOIN    gold.DimProduct  AS p ON p.ProductID = s.ProductID
JOIN    gold.DimCustomer AS c ON c.CustomerID = s.CustomerID AND c.IsCurrent = 1
GROUP BY d.DateKey, p.ProductKey, c.CustomerKey;
  1. CTAS creates the table: no CREATE TABLE needed first.
  2. Swap business keys for surrogate keys and aggregate.
  3. Join dimensions; only the current SCD2 version of customers.
  4. Pre-aggregated to daily grain: one set-based step, no data movement.

Deep dive: COPY INTO fine print, idempotent reloads
  • Parquet: column names must match exactly (non-matching target columns get NULL); type errors fail regardless of MAXERRORS.
  • Firewalled storage: Entra ID or Workspace Identity + resource instance rule (trusted workspace access). OneLake sources: Entra ID or workspace identity.
  • A low-privileged loader doesn't need CONTROL on the warehouse.
  • Idempotent day reload: DELETE … WHERE DateKey = 20261103; then INSERT … SELECT … WHERE OrderDate = '2026-11-03'.

Time travel, clones & restore points

The retention window (default 30 days) is your safety net: query it, clone it, or roll back to it.

Recovery timeline
Clone: copy or reference?
Reference. Only metadata is copied; storage grows only as the tables diverge.
Clone across warehouses?
No. Within/across schemas of one warehouse only. Not on the SQL endpoint.
Who can restore in-place?
Workspace Admins only. User-defined restore points: Admin, Member, Contributor.
Who can time travel?
Any workspace role, including Viewer. RLS/CLS/masking still apply.
Time travel timestamp format?
UTC, yyyy-MM-ddTHH:mm:ss[.fff], max 3 fractional digits, once per statement.
  • Report on yesterday 18:00 UTC while ETL runs
  • Compare with last week without creating objects
  • Testers need a modifiable 2 TB table in seconds
  • Month-end snapshot table for auditors
  • Bad release corrupted many tables
  • Reset a dev warehouse before a migration test

Testers need a modifiable point-in-time copy of 2 TB dbo.FactSales with minimal storage and creation time. Use…

  • SELECT * INTO dbo.FactSales_Test FROM dbo.FactSales
  • A user-defined restore point
  • A pipeline Copy activity
  • CREATE TABLE dbo.FactSales_Test AS CLONE OF dbo.FactSales

A zero-copy clone references existing files. SELECT INTO and Copy duplicate 2 TB; a restore point restores everything.

Deep dive: clone, time travel and restore rules
  • Clone inherits object-level security, RLS, DDM and PK/unique constraints. Needs Admin/Member/Contributor, SELECT on all source data, CREATE TABLE on the target schema. Groups of tables can be cloned at the same point. No warehouse/schema-level clone.
  • Time travel queries must start with SELECT; usable in procedures and to query a view as of a time, but not inside a view definition. Returns the latest schema; dropping and recreating a table loses history.
  • Restore points copy metadata only; ≥ 20 kept with ≥ 30-day retention; system ones (RPO 8 h) can't be deleted. Restore in-place keeps the same name (no restore to a new warehouse) and also rolls back Query Insights and modelling.
  • Deleted warehouse items: tenant item recovery (dropped item retention).

Programmability & monitoring

Procedures load, statistics guide the optimizer, Query insights show what was slow.

  • Views: friendly names; GRANT on the view, not the table. Visual query editor can save one without code.
  • Inline TVFs and procedures; call procedures from a pipeline Stored procedure activity.
  • Load pattern: BEGIN TRY / BEGIN TRAN … COMMIT / CATCH ROLLBACK; THROW.
  • Views in Direct Lake on SQL endpoint models → fallback. Materialise with CTAS.
  • Auto-created for JOIN/WHERE/GROUP BY columns (_WA_Sys_…), auto-refreshed.
  • Estimates far from actuals after a big load → UPDATE STATISTICS first.
  • Manual stats: single-column only. Inspect: DBCC SHOW_STATISTICS.
  • Always snapshot isolation: readers and writers don't block.
  • Table-level conflicts: two UPDATE/MERGE on one table → later commit fails, retry.
  • INSERTs rarely conflict. DDL blocks reads: run in maintenance windows.
  • queryinsights.exec_requests_history: completed queries, 30 days, ~15 min delay.
  • long_running_queries, frequently_run_queries, sql_pool_insights.
  • Live: sys.dm_exec_requests (+ KILL). Capacity: Metrics app.
  • In-memory + SSD cache: automatic, can't be cleared.
  • Result set caching on by default; off per item or per query hint.
  • Separate SELECT and ingestion pools isolate workloads.

  • Create a clustered columnstore index
  • Restore from a restore point
  • UPDATE STATISTICS on join/filter columns

Stale statistics; indexes aren't available.

Deep dive: caching rules, query insights, hygiene
  • Result set caching skipped for: cross-database queries, time travel, RLS/DDM, non-deterministic functions, results > ~10,000 rows, changed tables. Disable: ALTER DATABASE … SET RESULT_SET_CACHING OFF or OPTION (USE HINT ('DISABLE_RESULT_SET_CACHE')).
  • Query insights aggregates similar queries by query hash; works for warehouses and endpoints; cross-database queries appear in the item you connected to. Also exec_sessions_history, external_api_call_stats.
  • Transactions can span warehouses in the same workspace; update-conflict errors 24556/24706. Not supported: distributed, named, marked transactions, savepoints. Locks: sys.dm_tran_locks.
  • Hygiene: right-size types, integer keys, batch trickle INSERTs, avoid SELECT *, filter early.

Finance migrates a SQL Server DW: (1) Parquet from firewalled ADLS, (2) surrogate keys, (3) trigger-based audit, (4) sprint test copies, (5) reversible releases. Design?

(1) COPY INTO with Workspace Identity + trusted workspace access (or pipeline Copy). (2) BIGINT IDENTITY. (3) Audit rows in load procedures (same transaction). (4) Zero-copy clones. (5) User-defined restore point before each release; Admin restores in-place. Orchestrate: Copy → Stored procedure → model refresh.

Exam traps

  • "Analysts must UPDATE rows with T-SQL" → warehouse, not the SQL endpoint.
  • Triggers are unsupported; IDENTITY and MERGE are supported.
  • PK/FK/UNIQUE are NOT ENFORCED: duplicates get in.
  • COPY INTO needs an existing table; CTAS creates one.
  • Clones don't cross warehouses or workspaces.
  • Restore in-place replaces the whole warehouse; only Admins can do it.
  • sys.dm_exec_requests = running now; exec_requests_history = completed.
