Deep dive: editor details
  • Queries are saved in My queries or Shared queries; viewers and shared recipients can't move queries to Shared queries.
  • Multiple result sets: pick one from a dropdown. GO starts a new batch; SET options and sp_set_session_context don't persist across runs.
  • Copilot: inline completion, Explain (Ctrl+Alt+E), Fix query, chat that writes T-SQL.
  • Add other warehouses / endpoints of the same workspace to the Explorer to query them with three-part names; data is read in place.

Visual query editor (no code)

Drag tables, click Power Query steps, and Fabric folds them into one T-SQL SELECT.

🧲 Drag tables from the Explorer onto the canvas, even from several added warehouses or endpoints.

🧱 Choose columns, filter, sort, group by, merge (= join), append (= union). Only foldable steps work; otherwise a banner says the query isn't supported.

🔍 View SQL shows the generated SELECT; Edit SQL script opens it in the SQL editor. With merges, only the query with Enable load is scripted.

💾 Save as view (pick schema, review SQL) or Save as table (CTAS). Or Download Excel file / Visualize results.

Window functions

A window function adds a value to every row from related rows, without collapsing them like GROUP BY.

Window function visualizer: watch the new column change
500, 400, 400, 300 with RANK?
1, 2, 2, 4 (gap)
… with DENSE_RANK?
1, 2, 2, 3 (no gap)
… with ROW_NUMBER?
1, 2, 3, 4 (tie order arbitrary)
Can you use a window function in WHERE?
No. Wrap it in a CTE or subquery and filter outside.
WITH ranked AS (
    SELECT *,
           ROW_NUMBER() OVER (PARTITION BY CustomerID
                              ORDER BY ModifiedDate DESC, LoadId DESC) AS rn
    FROM   stg.CustomerChanges
)
SELECT * FROM ranked
WHERE  rn = 1;
  1. A CTE names a query-scoped result set you can reference (and chain).
  2. One window per customer.
  3. Newest first; LoadId breaks ties so the result is deterministic.
  4. Filter outside the CTE: keep row 1 = latest version per customer.

Which ranking function returns 1, 2, 2, 3 for 500, 400, 400, 300 (descending)?

  • ROW_NUMBER()
  • RANK()
  • NTILE(3)
  • DENSE_RANK()

DENSE_RANK has no gaps; RANK gives 1, 2, 2, 4.

Deep dive: more window patterns 
AVG(SalesAmount) OVER (ORDER BY OrderDate ROWS BETWEEN 6 PRECEDING AND CURRENT ROW) AS MovingAvg7,
SalesAmount * 1.0 / SUM(SalesAmount) OVER (PARTITION BY CustomerKey)              AS ShareOfCustomer,
NTILE(4) OVER (ORDER BY SalesAmount DESC)                                          AS Quartile

LAG/LEAD(col, offset, default). Without an explicit frame, a window with ORDER BY uses RANGE … CURRENT ROW, which groups ties: specify ROWS for running totals.

Deep dive: PIVOT, dates and strings 
SELECT CalendarYear, [Bikes], [Accessories], [Clothing]
FROM ( SELECT d.CalendarYear, p.Category, f.SalesAmount FROM … ) AS src
PIVOT ( SUM(SalesAmount) FOR Category IN ([Bikes], [Accessories], [Clothing]) ) AS pvt;

STRING_AGG(ProductName, ', ') WITHIN GROUP (ORDER BY ProductName)

UNPIVOT reverses PIVOT. Date/string helpers: DATEFROMPARTS, EOMONTH, DATEADD, DATEDIFF, DATEPART, DATENAME, CONCAT, TRIM, COALESCE, SUM(CASE WHEN … THEN 1 ELSE 0 END). APPROX_COUNT_DISTINCT is fine for dashboards, not for financial reconciliation.

DAX queries & DAX query view

A DAX query returns a table from a semantic model: exactly what every Power BI visual sends.

DEFINE
    VAR _Year = 2026
    MEASURE Sales[Total Sales] = SUM ( Sales[SalesAmount] )
    MEASURE Sales[Margin %] =
        DIVIDE ( [Total Sales] - SUM ( Sales[TotalCost] ), [Total Sales] )
EVALUATE
    SUMMARIZECOLUMNS (
        'Date'[Year],
        Product[Category],
        TREATAS ( { _Year }, 'Date'[Year] ),
        "Sales", [Total Sales],
        "Margin %", [Margin %]
    )
ORDER BY [Sales] DESC
  1. DEFINE (optional): query-scoped VAR, MEASURE, TABLE, COLUMN. Nothing is saved yet.
  2. EVALUATE (required) returns a table. Several EVALUATEs = several result sets.
  3. SUMMARIZECOLUMNS = GROUP BY. Rows where all measures are blank are removed.
  4. A filter argument: like WHERE, applied as filter context.
  5. Named measure columns.
  6. ORDER BY (optional) sorts the output; START AT pages.

  • Copy the query into Performance Analyzer

Web DAX queries need write permission. Models have no visual query editor or SQL endpoint.

Deep dive: limits and storage of query tabs
  • Works on Import, DirectQuery, Direct Lake and composite models.
  • Tabs are saved in the .pbix; in a PBIP project each tab is a .dax file in the DAXQueries folder. In the web, tabs are discarded on close.
  • Desktop: 15 MB / 1,000,000 values per query. Web: max 99,999 rows, needs write permission and the workspace setting Users can edit data models in the Power BI service.
  • Live connection: model measures can't be edited; quick queries limited to Evaluate; report measures must be in DEFINE and can't be pushed with Update model.
  • Define / Define with references light-bulb actions only appear when the tab has no DEFINE yet. TOPN may return more rows on ties.

(d) A data scientist needs order-value distribution over 4 billion rows and the model's Total Sales in Python. Which tool for each?

  • (b) DAX query view: Define with references, group by Product[Category]; or Performance Analyzer → Run in DAX query view.

Exam traps

  • The SQL analytics endpoint is read-only for tables, but views, functions and security work.
  • Each Run is its own session: no BEGIN TRAN in one run and COMMIT in the next.
  • No linked servers: use three-part names within the workspace.
  • The visual query editor only supports foldable steps and is read-only.
  • RANK has gaps; DENSE_RANK doesn't; window functions can't go in WHERE.
  • DEFINE MEASURE is query-scoped until you choose Update model with changes.
  • Power Query profiles only the top 1,000 rows by default.
  • Visualize results isn't available when the query has ORDER BY.
