Files/Raw is a shortcut to ADLS Gen2. A user with write access on the storage deletes Files/Raw/2025 in the lakehouse. Result?

  • Only the shortcut definition is removed
  • Nothing: shortcuts are read-only
  • The 2025 folder is deleted from the ADLS container
  • It goes to the lakehouse recycle bin for 7 days

Deleting through a shortcut deletes in the target; deleting the shortcut itself never does.

A Tables shortcut points to a valid Delta table in another lakehouse. Which is true?

  • It's a table for the SQL analytics endpoint and Direct Lake
  • It can sit at any subfolder depth under Tables
  • It copies the Delta files on creation
  • Readers never need access to the target

Top-level Tables shortcuts to Delta are auto-discovered; internal shortcuts pass the user identity.

Deep dive: shortcut fine print
  • Create: Contributor+ on the item holding the shortcut + access to the target. UI (New shortcut) or OneLake shortcuts REST API; target can come from a variable library.
  • Exception to passthrough: Direct Lake on SQL endpoint and T-SQL delegated mode use the item owner's identity; Direct Lake on OneLake and T-SQL user identity mode use the user.
  • KQL database: appears under Shortcuts, query with external_table('MyShortcut').
  • Names with spaces aren't recognized as Delta tables; no % or + in names. 100 external connections per item; 10 shortcuts in one path.
  • Cache (workspace settings → OneLake): retention resets on each access; newer source versions fetched; Reset cache clears it.
  • Firewalled ADLS Gen2 → trusted workspace access: workspace identity + resource instance rule (F SKU).

How does mirroring an Azure SQL DB on an F64 capacity affect cost?

  • Replication consumes CUs and all storage is billed
  • A separate mirroring license per database
  • Everything is free, including queries
  • Replication is free, 64 TB storage free, queries consume CUs

Only queries and storage beyond 1 TB per CU (or while paused) cost.

Batch tools: Copy job, pipelines, Dataflow Gen2, notebooks

Copy job moves, pipelines orchestrate, dataflows reshape, notebooks code.

  • Write: append (default), merge (upsert), overwrite, SCD Type 2.
  • State managed: failed run resumes; reset to full per table.
  • Several schedules, or a Copy job activity in a pipeline; gateways, Git, variable libraries.

Order-dependent steps belong in one pipeline; separate schedules can't guarantee order.

REST APIs with OAuth, nested JSON, custom quality rules. Land raw payloads in Files (bronze), then Delta. Explicit schema for CSV; mergeSchema for new columns. Parameters cell, schedule, pipeline Notebook activity.

Lookup LookupWatermark (First row only) returns LastModified. Which expression feeds the next Copy?

  • @activity('LookupWatermark').output.value[0]
  • @pipeline().parameters.LastModified
  • @activity('LookupWatermark').output.firstRow.LastModified
  • @item().LastModified

First row only exposes firstRow; @item() exists only inside ForEach.

Deep dive: pipeline and dataflow fine print
  • Activities: Copy data, Copy job, Dataflow, Notebook, Spark job definition, Stored procedure, Script, KQL, Semantic model refresh; ForEach, If, Switch, Until, Wait, Filter, Set/Append variable, Invoke pipeline, Fail; Lookup, Get metadata; Web, Webhook, Azure Function, Outlook, Teams.
  • Parameters fixed per run (@pipeline().parameters.X); variables mutable. Notebook activity base parameters override the parameters cell. Expressions: @concat('raw/', formatDateTime(utcNow(), 'yyyy/MM/dd')).
  • Copy activity: staging (e.g. on-prem → warehouse through a gateway), fault tolerance (skip + log bad rows), parallel copies, partitions, gzip/zip natively.
  • Schedules per item with time zone; Copy jobs can have several. Event triggers (file arrives, job events) via Real-Time hub / Activator.
  • Dataflow Gen2 (CI/CD) supports Git, deployment pipelines, public parameters, variable libraries. Destinations: lakehouse, warehouse, KQL DB, SQL DB, Azure SQL, ADX, ADLS Gen2, SharePoint, Snowflake, PostgreSQL; one per query. Existing table: dataflow never recreates a deleted table. Dynamic schema: table dropped/recreated on schema change.
  • Split big work: query A (staging) ingests, query B references it and writes. Put foldable steps (filter, remove columns, group by) early; a non-folding step pulls everything before it into the mashup engine.
  • Dataflow incremental refresh ≠ semantic model incremental refresh (RangeStart/RangeEnd).

Deep dive: connections

Settings → Manage connections and gateways. A connection stores endpoint, auth method (OAuth, service principal, workspace identity, key, SAS, basic) and privacy level. Roles: Owner, User, User with resharing. Binding an item or shortcut to a connection needs permission on it.

"Don't move what you only need to read." Shortcut or mirror first; copy only for independence, transformation or unsupported sources.
Promoted vs Certified?
Promoted: anyone with write on the item. Certified: only admin-authorized users. Master data: admin-designated owners.
Import model tables as Delta for Spark?
Turn on OneLake integration for the model; after refresh, shortcut the tables into a lakehouse.

A team writes all logic in T-SQL and needs multi-table transactions and UPDATE/DELETE. Data arrives as Parquet in ADLS Gen2. Best fit?

  • Lakehouse via Dataflow Gen2, edited through the SQL endpoint
  • Eventhouse with an eventstream
  • Files shortcut queried with T-SQL views
  • Warehouse loaded with COPY INTO

The lakehouse SQL endpoint is read-only; the warehouse has full DML.

Scenario: 15 TB S3 clickstream, Azure SQL orders at minute latency, freezer telemetry in Event Hubs (alert above 8 °C for 5 min), monthly SharePoint Excel budgets, nightly incremental on-prem SQL Server ERP. Pick each.

  • S3 → shortcut + caching.
  • Azure SQL → mirroring.
  • Telemetry → eventstream → eventhouse + Activator.
  • Budgets → Dataflow Gen2.
  • ERP → on-prem gateway (cluster) + Copy job incremental (or Lookup/ForEach pipeline).
Deep dive: OneLake catalog and OneLake integration
  • OneLake catalog (successor of the OneLake data hub): Explore (filter by type, workspace, domain, endorsement, tags; lineage, schema) and Govern tabs; embedded in Get data dialogs. Items can be discoverable for users without access, who then request it.
  • Reuse a model: endorse, make discoverable, grant Build.
  • Semantic model OneLake integration (Import, P/F capacity): measures, DirectQuery/hybrid tables and calc groups not exported; old versions kept 3 days.
  • Mirrored DBs and SQL databases also land Delta in OneLake; one curated copy serves all engines (cross-database queries, shortcuts).

Exam traps

  • Deleting a shortcut keeps the target; deleting files inside it deletes them in the target.
  • No shortcuts in a warehouse; Tables shortcuts only at the top level.
  • Internal shortcut = user needs permission on the target; external = connection credentials.
  • Mirroring replication is free; queries are not. Paused capacity = no replication.
  • Personal gateway never serves Fabric items.
  • Dataflow to warehouse needs staging; fast copy writes directly only to a lakehouse.
  • Lakehouse SQL analytics endpoint is read-only.
  • Separate schedules don't guarantee order: chain steps in one pipeline.
